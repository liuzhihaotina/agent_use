执行步骤：

1. **识别变更**：先跑 `git diff --name-only` 与 `git diff --name-only --cached`，列出本次涉及的文件
2. **挑选命令**：按 [`test 子代理`](../agents/test.md) §2 的命令选择策略，挑**最窄且能证明改动有效**的命令
3. **执行**：用 `bash: ask` 跑命令，记录完整输出
4. **汇报**：按下列结构输出

```markdown
### 🧪 执行的命令
```bash
<具体命令>
```

### 📊 结果
- 状态：✅ 通过 / ❌ 失败 / ⚠️ 跳过
- 计数：N passed, M failed, K skipped
- 关键输出：
  ```
  <截取最相关的 5–20 行>
  ```

### 🎯 覆盖到的场景
- ……

### 🕳️ 未覆盖到的场景
- ……

### 💡 备注
- 为什么选这个命令（与其它候选的对比）
- 如失败：是否建议委派 `debug`
```

> 反模式：不假思索跑全量套件、失败后反复重试到通过、伪造结果。
