---
description: 通过日志、堆栈或定向命令复现并分析失败，定位根因并给出最小修复路径。
---

按 [`debug 子代理`](../agents/debug.md) 的"调试七步法"推进：

```
复现 → 隔离 → 二分 → 假设 → 验证 → 修复 → 回归
```

最小起步动作：

1. **收集证据**
   - 让用户提供：失败现象 / 报错日志 / 触发输入 / 期望行为
   - 自动跑：`git log --oneline -10`（最近改动嫌疑）、`git status`（工作区状态）

2. **尝试复现**
   - 选最便宜的复现方式：单测 / 命令行脚本 / 局部启动
   - 失败要记录精确命令与环境

3. **缩小范围**
   - 如怀疑近期 commit：`git bisect` 或手动二分
   - 如怀疑数据：用最小输入构造同样失败

4. **下结论 + 修复路径**
   - 按 [`debug 子代理` §4 输出格式](../agents/debug.md) 给出：根因、修复、验证计划、风险

5. **回归保护**
   - 必须建议补一条测试用例（即使本次不写）

> 反模式：跳过复现直接猜 / 一次列十种可能根因 / 用 try/except 掩盖问题 / 借调试名义重构无关代码。
