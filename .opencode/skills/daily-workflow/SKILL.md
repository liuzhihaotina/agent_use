# 日常工作流

这是日常工程任务的默认开发工作流。

## 目标

以最小风险把任务从需求推进到可验证结果。

## 标准流程

1. **理解**
   - 先阅读相关代码、测试和配置。
   - 确认预期行为与验收标准。

2. **计划**
   - 将多步骤工作拆成小任务。
   - 步骤超过一个时使用 TODO 跟踪。

3. **实现**
   - 只做能解决问题的最小改动。
   - 优先局部修复，避免大范围重构。

4. **审查**
   - 检查正确性、回归、边界条件和遗漏测试。
   - 需要时使用审查代理做二次检查。

5. **验证**
   - 运行最相关的测试、lint 或构建命令。
   - 优先选择最窄且能证明修改有效的命令。

6. **调试**
   - 先复现失败，再修改代码。
   - 缩小根因范围，只修必要部分。

7. **汇报**
   - 说明改动内容。
   - 列出验证命令和结果。
   - 说明风险、假设与后续事项。

## 代理协作建议

- 代码改动后，如可能影响行为，使用 `review`。
- 需要明确验证时，使用 `test`。
- 需要复现或隔离失败时，使用 `debug`。

## 输出格式

- 摘要
- 修改文件
- 验证结果
- 剩余风险

重要引用请使用 `path:line`。
