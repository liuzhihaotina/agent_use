# 日常工作流（Daily Workflow Skill）

> 这是"做一件不大不小、不绕弯子"的事时的**轻量 SOP**。
> 如果任务涉及实质性代码改动，请改用 [`code-workflow`](../code-workflow/SKILL.md)。

---

## 1. 触发场景

- 帮我看一下 / 解释一下某段代码
- 帮我写一段简短脚本 / 单文件改动
- 帮我查一下 git log / 找一下某个调用
- 帮我汇总一下 README / 配置 / 依赖
- 日常零散问答与探索性分析

> 判别准则：**不会引入跨模块影响、不需要委派子代理、不需要长 TODO**，就走这里。

---

## 2. 四步轻量流

```
读 → 想 → 做 → 报
```

1. **读**：把任务涉及的 1–3 个最相关文件读完
2. **想**：在心里过一次"做完之后怎么验证"
3. **做**：最小改动 / 直接答复
4. **报**：用 [`AGENT.md` §7 标准汇报模板](../../../AGENT.md) 的精简版回报

精简版示例：
```markdown
### ✅ 结论
（1–2 句话）

### 📂 涉及文件（如有改动）
- `path/to/file.ts:42`

### 🧪 验证（如有改动）
- `<命令> → <结果>`
```

---

## 3. 何时升级到 code-workflow

满足下列任一即升级：

- 改动涉及 ≥ 2 个文件
- 需要新建 / 删除文件
- 修改了对外接口、配置、数据库 schema
- 你心里浮现"这里需要补一条测试"
- 你心里浮现"这个改动有点风险"

---

## 4. 反模式

- ❌ 把"日常任务"扩大成顺手重构
- ❌ 不读相关文件就给答复
- ❌ 改了文件却不说"改了什么、怎么验证"
