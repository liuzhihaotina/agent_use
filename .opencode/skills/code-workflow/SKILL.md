# 代码工作流

将此技能作为代码变更任务的默认工作流。

## 触发场景

- 用户要求修改代码
- 用户要求审查变更
- 用户要求验证、测试、回归检查
- 用户要求完成一个从分析到落地的代码任务

## 工作流

1. **明确目标**
   - 确认要改什么、预期行为是什么、验收标准是什么。
   - 不清楚时先问最关键的问题。

2. **定位现有实现**
   - 先看相关文件、调用链、测试和配置。
   - 优先理解现状，再设计最小改动。

3. **拆解任务**
   - 对多步骤任务使用 TODO。
   - 将“修改 / 审查 / 验证”视为独立步骤。

4. **实施变更**
   - 只修改必要文件。
   - 保持风格一致，避免无关重构。
   - 如果有多个实现方案，优先选择可验证、风险最低的方案。

5. **验证结果**
   - 优先跑最相关的测试、lint、构建或脚本。
   - 如果验证失败，继续定位问题并修复。
   - 如果无法验证，要明确说明原因。

6. **输出结论**
   - 简要描述改动。
   - 列出验证命令和结果。
   - 指出遗留风险或后续建议。

## 审查清单

- 行为是否符合预期
- 是否有边界条件遗漏
- 是否引入回归
- 是否需要补测试
- 是否需要更新文档或注释
